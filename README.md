# Mini NPU Simulator

## 실행 방법

1. 터미널에서 작업 디렉터리를 `e1_3`로 이동합니다.
2. `python main.py`를 실행합니다.
3. 화면에 표시되는 모드 선택에서 `1` 또는 `2`를 입력합니다.

- `1`: 사용자 입력 모드 (3×3 필터 A, B와 3×3 패턴 입력)
- `2`: `data.json` 분석 모드

`data.json` 파일은 현재 디렉터리에 있어야 하며, 프로그램은 해당 파일을 읽어서 `filters`와 `patterns`를 처리합니다.

## 구현 요약

- 입력 검증
  - 사용자 입력 모드에서 3×3 필터와 3×3 패턴을 한 줄씩 공백 구분 숫자로 입력받습니다.
  - 행 길이 또는 숫자 파싱 오류가 발생하면 재입력을 유도합니다.
  - 오류 메시지는 `입력 형식 오류: 각 줄에 3개의 숫자를 공백으로 구분해 입력하세요.`로 출력됩니다.

- 라벨 정규화
  - `expected` 값 `+`는 `Cross`로, `x`는 `X`로 내부 정규화합니다.
  - 필터 이름 `cross`는 `Cross`, `x`는 `X`로 출력 및 비교합니다.

- MAC 연산
  - `mac_score` 함수는 NumPy 같은 외부 라이브러리 없이 중첩 반복문으로 요소별 곱을 모두 더합니다.
  - 3×3 입력 모드와 `data.json` 분석 모드 모두에서 동일한 함수가 사용됩니다.

- 동점 처리
  - `EPSILON = 1e-9`을 사용하여 `abs(score_a - score_b) < 1e-9`이면 동점으로 처리합니다.

## 결과 리포트

- `data.json` 분석 모드에서는 패턴별로 `Cross` 점수, `X` 점수, 판정, 예상값, PASS/FAIL 여부를 출력합니다.
- `data.json` 내에서 스키마 또는 크기 불일치가 발생해도 프로그램은 중단되지 않고 해당 케이스를 `FAIL`로 처리합니다.
- 실패 케이스가 있는 경우, 패턴 키와 실패 원인을 함께 출력합니다.

### 실패 원인 분석

현재 구현은 다음 이유로 실패를 최소화합니다.
- `expected` 값을 내부적으로 `Cross`/`X`로 정규화하기 때문에 입력값 표기 차이(`+`, `x`)로 인한 불일치가 없습니다.
- MAC 연산 값 비교에 `EPSILON`을 적용하므로 부동소수점 오차로 인한 잘못된 판정이 줄어듭니다.
- 패턴 또는 필터 크기 불일치가 발생하면 케이스 단위로 `FAIL` 처리하고, 프로그램은 계속 실행됩니다.

### 성능 분석 및 시간 복잡도

- 각 `data.json` 패턴은 `Cross` 필터와 `X` 필터에 대해 각각 10회씩 MAC 연산을 수행하여 평균 수행 시간을 계산합니다.
- MAC 연산은 중첩 반복문으로 `N×N` 요소를 모두 순회하므로 시간 복잡도는 `O(N^2)`입니다.
- 출력 표에는 `크기`, `평균 시간(ms)`, `연산 횟수(N^2)`가 포함됩니다.

## 재현성

- 모드 1: 3×3 필터 A, B와 패턴을 예시대로 입력하면 점수와 판정, 평균 시간 출력이 정상 동작해야 합니다.
- 모드 2: `data.json` 분석 시 각 패턴이 `PASS`/`FAIL`로 판정되고 총합이 정확히 집계되어야 합니다.

## 추가 설명

- 외부 라이브러리는 사용하지 않았습니다.
- `main.py`는 `json`, `time`, `statistics`, `sys` 표준 라이브러리만 사용합니다.
- `data.json` 스키마는 `filters`와 `patterns` 구조를 전제로 합니다.
